=== ThinkPHP 登录限流（2026-10-14）===

## 两个维度（与 Laravel 侧同一套语义）
  per_ip       每 IP 每窗口 20 次
  per_account  每 IP 对每账号每窗口 5 次

  叠加的原因：只按 IP 限流的话，攻击者换 IP 就能继续猜同一个账号。

## 实测
  连续错误密码（per_account=3 的收紧配置）：
    第 1~3 次 → HTTP 401 账号或密码不正确
    第 4~5 次 → HTTP 429 尝试过于频繁，请 60 秒后重试
  per_ip 维度（换不同账号名）：第 21 次 → HTTP 429
  成功登录清零：3 次错误 → 正确密码 302 → 再错误仍是 401（不是 429）

## e2e 断言（81/81 的第 ⑧ 节）
  前几次是 401（密码错误）
  达到上限后变 429（限流）       HTTP 401,401,401,401,401,429,429
  429 提示剩余秒数              （只说「太频繁」用户不知道等多久）
  正确密码仍可登录（未被误伤）

## 一个设计取舍
  没有直接用 TP 的 think\middleware\Throttle —— 它按**路由**限流、且只按 IP。
  登录需要「按账号」维度，否则换 IP 就能继续猜同一个账号。

## 顺带踩到的一个测试夹具问题
  限流按 IP 计数，而 e2e 自己就要发十几次登录请求 ——
  上一轮的计数会跨轮次影响，断言看到的是上一轮的 429。
  夹具现在会在开始前显式清掉限流缓存。
