> 配套可视化展厅：`05-schemes.html`（双击打开，含每个方案的真实渲染截图级 mockup）

## 〇、先说根因（这是前几版被否决的真正原因）

对 `packages/framework/resources/assets/logo.png` 做逐像素 HSV 统计（排除近白/近黑/近灰）：

| 色相 | 占比 | 色值 | 在 LOGO 里的位置 |
|---|---|---|---|
| 210–225° 蓝 | **61.8%** | `#21559a` / `#205098` | 外圈圆环 + 代码图标 + 人像 |
| 105–120° 绿 | 15.7% | `#70d070` | "nong" |
| 0–15° 橙红 | 9.0% | `#e05040` | "Ai" |
| 30–45° 橙黄 | 8.6% | `#e8a840` | "m a n" |

**LOGO 本身是四色相的品牌资产。而 v3「Terminal Blueprint」把它压成了一个蓝色相。**

这就是「闷 / 太单」的第一性原因 —— 不是饱和度调得不够好，是**色相数量从一开始就被砍掉了 3/4**。

配合另外三条：

| 用户反馈 | 实测证据 | 结论 |
|---|---|---|
| 颜色太闷/太单 | 单一蓝色相，品牌 4 色相被丢弃 | ✅ 成立 |
| 布局太普通 | `--w-sidebar:236px` + `--h-topbar:52px` + 内容区，与 AdminLTE 2015 同构 | ✅ 成立 |
| 缺少视觉冲击 | 最大字号 26px；最大色块是白卡片；唯一渐变是 3% 白光晕 | ✅ 成立 |
| 细节不精致 | 等宽字体被用于中文（面包屑/表头/SLUG）；hairline 是 1px 而非 0.5px | ✅ 成立 |

**关键修正**：精致不来自「用了等宽字体」，而来自 **alpha 台阶 + 亚像素描边**。
Linear 用 1%~25% 白的 9 档、Vercel 用 10 级灰 + 10 级 alpha、Clerk 暗色用 2.5% 白 inset。

## 一、视觉语言解剖（11 个产品，实测值）

### 1. Linear · 冷静精密

- **视觉签名**：① 光晕是**数学不是模糊** —— 把 6% 白 tint 手工切成 8 段 alpha
  （`100→94→78→58→35→16→3→0%`）用 `color-mix` 逐段递减，替代 `filter:blur`；
  ② `--border-hairline: .5px` 亚像素描边。
- **色值**：主 `#5E6AD2`（**只做「面」**：按钮底/焦点环/选区）·
  强调 `#7170FF` / `#828FFF`（**只做「字与线」**）·
  画布 `#08090a`，四级 `#08090a → #0f1011 → #141516 → #191a1b` ·
  边框 `#23252a` / 6% 白 `#ffffff0f` ·
  文字 `#f7f8f8` / `#d0d6e0` / `#8a8f98` / `#62666d`
- **渐变**：描边 `linear-gradient(135deg,#ffffff26 0%,#ffffff0d 25%) border-box`；
  hero `linear-gradient(180deg,#08090a 10%,#d0d6e0 100%)` —— **用文字色当背景亮部**
- **尺寸**：侧栏 232px · 顶栏 72px（≤640 降 64）· 圆角 4/6/8/12/16/24/32 ·
  正文 15px/1.6/**-0.011em** · 标题 17→72px · 导航项高 28px、**项间距仅 2px** ·
  字重 300/400/**510/590/680**（刻意避开 500/600/700）
- **冲击来源**：近黑画布 + 亚像素结构 + 局部光源。**没有一处饱和色铺大面积**
- **细节**：active `scale(.97)` · hover `brightness(1.08)` · 过渡 `.16s ease-out-quad` ·
  图标 12/16/18px · focus `2px solid + offset 2px`
- **怎么不闷**：4 级近黑台阶 + 9 档白 alpha 台阶 + 大面积中性配极小面积高饱和 +
  外来彩色 logo 一律 `grayscale` 强制单色化
- **中文坑**：字重 510/590 **无法映射**中文字体；负字距对中文必须归零；
  15px 对中文偏小（建议 16px / 行高 1.75–1.8）；Berkeley Mono 不含中文字形

### 2. Vercel / Geist · 黑白极简

- **视觉签名**：**边框不是 border，是阴影环** —— `0 0 0 1px #00000014`（光）/
  `0 0 0 1px #ffffff25`（暗）。这样描边能贴合任意圆角，消除 border 在圆角处的取整毛刺。
  官方文档把「叠加 alpha 边框」列为禁止项。
- **色值**：文字 `#171717`（暗 `#ededed`）· focus `#0072f5`（暗 `#50a8ff`）·
  画布 `#fafafa`（暗**纯黑 `#000000`**）· 卡片 `#ffffff`（暗 `#0a0a0a`）· 边框 `#ebebeb`
- **灰阶语义（10 级每级绑死角色）**：100 静止底 / 200 hover 底 / 300 active 底 /
  400 默认边框 / 500 hover 边框 / 600 active 边框 / 700 填充 / 800 填充 hover /
  900 次级文字 / 1000 主文字
- **渐变**：develop `linear-gradient(90deg,#007cf0,#00dfd8)`；
  preview `#7928ca → #ff0080`；ship `#ff4d4d → #f9cb28`；
  conic 环形高光 `conic-gradient(from 218deg,…#ffffffb8 82deg…)`
- **尺寸**：侧栏 260px · 顶栏 64px · 圆角 控件 6 / 卡片 8 / 浮层 12 / 全屏 16 ·
  间距 4px 基准 · 控件高 32/40/48 配内边距 6/10/14 ·
  标题 `72px/72px/-4.32px 600`（**负字距约 -6%**）
- **冲击来源**：① 全站只有 1 种边框粗细 ② 10 级灰阶读出 10 个层级
  ③ 极端负字距把字块压成紧密灰矩形 ④ 99% 灰 + 极少量高饱和
- **细节**：阴影永远「多段小偏移 + 1px 环」；**按钮永不投影**；
  focus 环两层先铺 2px 底色再描 2px 蓝
- **中文坑**：负字距必须归零（汉字满框，-6% 会笔画相撞）；官方 label 行高仅 1.14–1.43

### 3. Raycast · 暗色玻璃 + 硬件质感

- **视觉签名**：① **玻璃不靠模糊靠固定配方** ——
  `linear-gradient(137deg,#111214bf 4.87%,#0c0d0fe6 75.88%)`
  + `backdrop-filter:blur(10px)` + `border:1px solid #ffffff0f`
  + `inset 0 1px 1px #ffffff26`。这个 137deg 与两个 stop 位置全站完全一致；
  ② 品牌红 **只做标点色**；需要大面积红时改用 3px 暗红发光细线
  `linear-gradient(90deg,#452324 0%,#eca5a7 93%,#581d27 100%)`
- **色值**：画布 `#07080a`（R7 G8 B10，**蓝通道最高**）· 面 `#101111` ·
  边框 `#242728` · 文字 `#f4f4f6`/`#c2c7ca`/`#9c9c9d` · 红 `#FF6363` ·
  冷色 `#57c1ff`/`#59d499`/`#ffc533`
- **辉光**：`conic-gradient(from 136.95deg,#0294fe,#ff2136,#9b4dff,#0294fe,#ff2136)`
- **冲击来源**：**把网页按键当硬件做** —— 键帽用
  `radial-gradient(75% 75% at 50% 91.9%,#151515,#0d0d0d)`（光源从键帽底部往上打）
  + 5 层 box-shadow + `:active translateY(2px)` + 红色辉光

### 4. Stripe · 明亮 + 渐变舞台

- **视觉签名**：品牌色换代 —— `#635bff` **只剩焦点环**，主按钮改走 `#533afd`；
  正文压到 **300 字重**，把全部饱和度让给渐变
- **色值**：accent `#00d4ff`/`#ff7a59` · 画布 `#fff` · 面 `#f8fafd`/`#f6f9fc` ·
  边框 `#e5edf5`/`#d4dee9` · 文字 `#0a2540`/`#425466`/`#697386` · Dashboard 主色 `#5469d4`
- **渐变**：日落 `radial-gradient(1660px 1064px at 50% 100%,#ffa577 0,#ff90a1 15.52%,#ddadff 30.09%,#ecd8ff 45.72%,#f5eaff 54.96%,#f8fafd 88.16%)`；
  统计卡 `270deg #ffd601,-380% → #ee30fb,-60% → #635bff,110%`
- **尺寸**：侧栏 250/280px（折叠 56）· 顶栏 48px · 圆角 **2/4/6px（极小）** ·
  控件 min-height 28/36/44、最常 40 · 正文 14px/1.4 w300 · hero 40px/1.1/-0.02em
- **冲击来源**：底缘巨型径向渐变当**舞台灯自下打上**；产品截图三层叠影
  `0 30px 60px -12px rgba(50,50,93,.25), 0 18px 36px -18px rgba(0,0,0,.3)`
- **细节**：1px 极浅 hairline 代替阴影做分隔 · 按钮 2/4px 微圆角 ·
  hover **只换色不位移** · 阴影靠上下双色而非单一黑
- **怎么不闷**：2 主色相（紫 14 阶 + 冷蓝灰中性）+ 6 组 accent

### 5. Supabase · 近单色 + 唯一强调

- **视觉签名**：**整套 UI 由单一 `--hue:157.5` + `--chroma:.005` 算出**，
  品牌绿只是同族偏移 4.4deg 的兄弟。所以「近单色」画布**天生带一丝绿味，不是纯灰** ——
  这就是它单色相却不显灰的原因。网格背景是 **2880 个 3px rect 的 SVG**，按索引相位错开
- **色值**：绿 `#3ECF8E` · 画布 `#131413` · 卡片 `#181A19`（= 画布明度 +.025）·
  边框 1px `oklch(.95 .001485 157.5/.075)` · 文字 `#ECEFED`
- **尺寸**：圆角 2.67/5.33/8/10.67/16px · 正文 Inter 16px/400 · H1 Manrope 46px/500 ·
  网格块 3px、间距 3.5px · 断点 520/600/720/768/960
- **冲击来源**：绿 `#3ECF8E` 明度 .527 压在画布 .19 上，是页面**唯一锚点**
- **细节**：卡片靠 **+.025 明度分层而非阴影**；图标 Lucide 24px stroke 2；
  微交互 = 网格方块 opacity .4s 按索引 +0.01s 错开

### 6. Sentry · 紫粉渐变 + 数据可视化

- **视觉签名**：hero 用 **88px 粗体**，且**只有一个词**硬编码跳出成 `#fd44b0`；
  渐变**只做结构带** —— `clip-path: polygon(0 0,100% 0,100% calc(100% - 3rem),0 100%)` + `opacity:.5`
- **色值**：主 `#6a5fc1` · 强调 `#fd44b0` + `#c2ef4e`(lime) · 画布 `#1f1633` ·
  卡片 `#181225` · 边框 `#362d59` · 文字 `#fff`/`#ececf1`
- **渐变**：`linear-gradient(149deg,#36166b 18.17%,#422082 56.94%,#4e2a9a 95.71%)`
  + 辉光 `radial-gradient(ellipse 50% 50%,rgba(173,108,170,.15),#1F1633 65%)`
- **尺寸**：圆角 4/6/8/12/16 · hero 88px/1.2、h2 60px、正文 16px/1.5 · 容器 1152px
- **细节**：按钮渐变**非静态**（`background-size:250%`，hover 滑动）；
  logo 是三轮 `stroke-dasharray` 循环描边
- **怎么不闷**：5–6 个色相**全部高饱和**；同色相多档串成渐变，紫↔粉↔橙邻近色互推，荧光绿单点爆点

### 7. PostHog · 大胆用色 + 插画

- **视觉签名**：**官方色板把「Red」定成橙 `#F54E00`、「Yellow」定成琥珀 `#DC9300`** ——
  名字与色相故意错位。底色拒绝纯白，用暖鼠尾草 `#EEEFE9`。
  明文规定「插画饱和度必须高于周边版式」。**明确禁用渐变背景**
- **色值**：底 `#EEEFE9` · 文字 `#151515` · accent `#E5E7E0` · 虚线 `#D0D1C9` ·
  Red `#F54E00` / Blue `#1D4AFF` / Yellow `#DC9300`（暗 `#F1A82C`）/ Gray `#BFBFBC`
- **尺寸**：圆角 2px 标签 / 4px 按钮输入 / 6px 卡片 · hero 30px/800/-0.75px ·
  h2 36px/700 · 正文 16px/1.5 · nav 15px/600 · 控件高约 40px
- **冲击来源**：**色块而非渐变** —— 奶油底上压高饱和橙/黄/蓝大色块 + 粗黑单线手绘插画
- **细节**：1px 鼠尾草灰边框、虚线分隔 · 卡片 4–6px **近直角** ·
  图标是等粗黑 monoline 手绘刺猬 · hover 文字闪 `#F54E00`
- **怎么不闷**：仅 3 主色；**高饱和只给插画，版式保持低饱和**

### 8. Clerk · 精致暗色 + 品牌渐变

- **视觉签名**：全站只留**一个**高饱和紫，渐变**只做光晕/时间轴指示，绝不填按钮**；
  暗色模式**取消所有投影**，改用 `inset 0 0 0 1px rgba(255,255,255,.025)` 分层
- **色值**：主 `#6c47ff` · 天蓝 `#00aee3 → #3ad4fd` ·
  画布 亮 `#f7f7f8` / 暗 `#131316` · 面 `#fff`/`#2f3037` · 边框 `#d9d9de`，暗 `#42434d`
- **尺寸**：H1 64px/700/-0.035em → H2 56 → H3 48 → H4 32 · 正文 18/15/13 ·
  mono 14/12 · eyebrow 11px/0.1em · 按钮高 30/26/24 · 圆角 6/8/12/16/9999 · 容器 1280
- **冲击来源**：暗段 `#131316` **直接摆真实产品 UI 截图当插画**，不给抽象图形
- **细节**：分割线 **0.5px** · 图标 16/20px stroke 1.25–1.5 round ·

### 9. Resend · 纯黑 + 排版张力

### 10. Framer · 超大字号 + 光效

### 从 11 个产品提炼的 5 条可复制规律

1. **没有任何高端产品靠「多色相」制造高级感。** Linear/Supabase/Resend/Framer/Clerk/Vercel
   全是单色相或近单色。它们不闷靠的是**中性色台阶足够多**（4–10 级）+ **极小面积高饱和锚点**。
2. **精致的物理来源是 alpha 台阶，不是字体。** 前几版把「用等宽字体」当成精致 —— 方向错了。
3. **冲击力来自「面积 × 对比」，不来自色相数量。** 共同点是**某一样东西被允许非常大**。
4. **暗色不等于黑。** Linear 最亮近黑 `#191a1b`、Raycast 画布蓝通道最高、
   Supabase 画布带 .005 彩度、Sentry 画布是紫 `#1f1633`。**纯灰黑才是「闷」的直接来源。**
5. **中文必须单独一套排版参数。** 所有产品的负字距对中文都得归零；
   官方 label 行高 1.14–1.43 对中文必须提到 1.6–1.8。**这条前几版完全没处理。**

## 二、5 个方案

> 每个方案都换了**骨架**（不只是颜色），且每个方案自带亮/暗两套值。
> HTML 展厅里可直接切换查看。

### 方案 A · 蓝图 Blueprint

**气质**：像 Linear 那样冷静精密 —— 但不是「暗色 + 蓝色」，而是「碳黑 + 亚像素结构 + 白色光源」。
**参考基底**：Linear

## 三、可行性评估

### 3.1 CSS 特性支持（实测，2026）

| 特性 | Chrome | Safari | Firefox | 全球覆盖 | 结论 |
|---|---|---|---|---|---|
| `backdrop-filter` | 76 | 9（需 `-webkit-`） | 103 | 97.08% | ✅ 可放心用，配不透明兜底 |
| `oklch()` | 111 | 15.4 | 113 | 95.12% | ⚠️ 只用于推导，产物写 hex |
| `color-mix()` | 111 | 16.2 | 113 | 94.79% | ⚠️ 可用，关键色写死回退 |
| `mask` / `mask-image` | 120 | 15.4 | 53 | 97.27% | ✅ 可放心用，Safari 需 `-webkit-` |
| `@property` | 85 | 16.4 | 128 | 96.13% | ✅ 可放心用 |
| `@container` | 106 | 16.0 | 110 | 95.89% | ⚠️ 建议用，配视口查询兜底 |
| `light-dark()` | 123 | 17.5 | 120 | 91.28% | ❌ 不要依赖，用现有 `data-mode` |
| **QQ 浏览器 14.9** | — | — | — | — | ❌ `oklch` / `color-mix` / 容器查询 / `backdrop-filter` **全不支持** |

**结论**：`backdrop-filter` / `mask` / `@property` / 渐变都可放心用；
`oklch` / `color-mix` 用来**生成**色阶但不要作为运行时唯一依赖 —— **所有令牌仍写最终 hex**。
这与现有 `themes.css` 的做法一致，**不需要改架构**。

## 四、我的推荐

### 首选：**A 蓝图**（暗色为主）

**理由**

1. **它解决「闷」的真正病因，而且不用赌。** 「闷」的根因是单色相 + 低饱和 + 大面积中性。
   A 的解法不是加饱和，而是**把中性色本身做出 4 级近黑台阶 + 1%–6% 的 alpha 台阶**，
   再用**一处高饱和强调色**做锚点。这是 Linear 被验证过的路径，
   也是唯一「既高级又不老气」的路径。
2. **它解决「布局太普通」而不用冒险。** 88px 图标轨 + 196px 上下文栏的三栏结构，
   在 1440px 上是「专业工具」，1024px 降为两栏，768px 变抽屉 —— 每档都有明确形态。
3. **它天生扣住品牌。** 「蓝图 / 代码 / 终端」的气质与 LOGO 的蓝色圆环 + 二进制数字同源，
   但**不再被蓝色绑死**：橙红/橙黄/亮绿降级为语义色（danger/warning/success）——
   这**恰好就是它们在 LOGO 里的原始角色**，有据可依。
4. **风险最低。** 暗色优先意味着「暗色好看」是免费的；反过来做则暗色要重调一遍。
   且它不需要任何浏览器新特性，QQ 浏览器 14.9 也能完整渲染。

### 备选：如果你判断用户就是嫌不够炸 → **B 新芽**

用户说「缺少视觉冲击」时，最直接的解药是**面积**，不是色相数量。
B 提供了五个方案里唯一一块会让人「哇」的东西：96px 顶栏 + 34px 彩色数字 + 顶部四色渐变条。
而且它是**亮色为主** —— 如果用户的审美偏好其实是「明亮、干净、不压抑」，
A 的暗色**反而会再次被判「闷」**。

> **这是我能给出的最重要的判断分歧点。**

### 诚实的工作量与风险

- **总工作量**：选定一个方案 → **1.5–3 人日**；再做一套亮/暗配套 → **+0.5 人日**。
  五个方案全部做成可切换主题是 6–8 人日，但**不建议** ——
  五个方案是**审美选择，不是产品功能**。
- **最大风险是「又一次审美否决」，而不是技术。** 技术上这些全在纯 CSS 能力内，
  零构建、零 CDN。
- **强烈建议的做法**：**先只做一个方案的一屏**（列表页，含表格），
  截图给用户看，确认方向再铺开。**这次不要再一次性做完三套主题了。**

### 已知技术坑（每个都有成熟解法，不构成阻断）

1. 0.5px 描边在 1x 屏会消失 → `@media (min-resolution:1.5dppx)` 分支
2. 中文负字距会撞笔画 → `:lang(zh){letter-spacing:0}`
3. 暗色硬阴影易脏 → 阴影色跟随描边色
4. 渐变在白底对比度不足 → 白底上改用深色文字 + `text-shadow` 兜底
5. 饱和黄/蓝大面积铺开 → 逐个校验对比度（展厅里已做）

### 不推荐的做法

**不要试图把五个方案「融合」成一个。** 它们的差异来自骨架与
圆角/描边的**体系性选择**，混搭会立刻退回「安全但平庸」—— 那正是被否决四次的根源。
