# 「做一个独属于 AI 码农的 Vue 前端」—— 必要性与路径分析

> 2026-10-16 · 基于对当前代码、6 轮 UI 历史文档、以及**实际运行界面的截图**的核对
>
> 所有数字都是**实测**的，不是估的。来源标注在每节里。

---

## 〇、结论先行

| 问题 | 结论 |
|---|---|
| 「前端没特色」这个判断对吗？ | **对。而且项目自己在 10-10 就诊断出根因了** |
| 有必要再做一轮「更好看的后台」吗？ | **没有。** 已经做过 6 轮，全是同一类迭代，边际收益已接近零 |
| 有必要做一个「独属于 AI 码农的前端」吗？ | **有，但不是"界面美化"，是"把框架的差异化做成界面"** |
| 要引入 Vite + Vue 组件库吗？ | **不要。** 与 2026-10-11 已决策的「零构建」直接冲突，理由在文档里 |
| 那具体做什么？ | 做 **1 个**面：**声明实验室 + 能力地图**。接口已经全部现成 |

**一句话**：问题不在审美，在于**6 轮全在装饰层面迭代，而"身份"只能从差异化能力里长出来** ——
而当前 UI 把框架的全部差异化能力都藏起来了（实测：一个都没暴露）。

## 一、先纠正一个前提：现在的 UI 不是粗制滥造

你说「没什么特色」，我以为是没做好。**实测之后不是**：

| 项 | 实测值 | 来源 |
|---|---|---|
| 设计系统 | **2016 行 / 64KB / 141 个 design token** | `packages/core/resources/assets/css/design-system.css` |
| 主题层 | 224 行，支持 `data-mode`（亮/暗）+ `data-density`（紧凑）+ `data-radius`（圆/方）+ `prefers-color-scheme` | `themes.css` |
| 对比度 | 方案称 **72 项校验全部通过**（3 主题 × 2 模式 × 12 项） | `UI与基座方案.md` §5.4 |
| Vue | **已本地化**（`vue.global.prod.js` 168KB），零外部 CDN | 实测模板引用 |
| 品牌色 | 从 LOGO 逐像素提取的 `#205098` 蓝 → `--brand-solid: #2d5ca4` | `themes.css:62` |

我用真实浏览器看了三个页面（登录页 / 控制台首页 / CRM 客户列表，1440×900）：

- **登录页**：分栏 + 渐变品牌面板 + 网格纹理 + 左侧特性清单 —— 比多数开源后台精致
- **控制台**：深色、卡片化、4 个统计块 + 35 个模块快捷入口 + 身份卡 + 系统信息
- **列表页**：数据表 + 语义徽章 + 分页 —— 干净、有层次

**所以「丑」不成立。** 但「没特色」成立 —— 下面说为什么。

## 二、为什么做了 6 轮还是「没特色」

### 2.1 六轮迭代全是同一件事

按时间排（全部集中在 **10-10 一天内**，01:23 → 13:45）：

| 轮次 | 产物 | 回答的问题 |
|---|---|---|
| `ui-redesign/` | design-system.css 49KB + README 74KB | 颜色/间距/圆角/暗色 |
| `ui-redesign-v2/` | aimanong-v3.css 46KB + README 59KB | 同上，第二版 |
| `ui-v3/` | prototype.html + 5 张截图 | 「Terminal Blueprint」 |
| `ui-options/` | **5 个视觉方向** + 22 张截图 | v1 终端 / v2 色彩铺开 / v3 亮色精密 / **v4 Agent 中心** / v5 极简 |
| `ui-reboot/` | 05-schemes.md 31KB + 展厅 107KB | 解剖 11 个产品（Linear/Vercel/Raycast/Stripe…）+ 5 方案 |
| `ui-final/` | B 新芽 vs C 纯白 对比 | 亮色二选一 |

**六轮，六次都在调「视觉语言」**：配色、字号、圆角、阴影、间距、暗色。

### 2.2 项目自己写下过根因（这句话很关键）

`internal-docs/ui-reboot/05-schemes.md` 第 11 节，标题就叫
**「〇、先说根因（这是前几版被否决的真正原因）」**：

> | 用户反馈 | 实测证据 | 结论 |
> |---|---|---|
> | 颜色太闷/太单 | 单一蓝色相，品牌 4 色相被丢弃 | ✅ 成立 |
> | **布局太普通** | `--w-sidebar:236px` + `--h-topbar:52px` + 内容区，**与 AdminLTE 2015 同构** | ✅ 成立 |
> | 缺少视觉冲击 | 最大字号 **26px**；最大色块是白卡片；唯一渐变是 **3% 白光晕** | ✅ 成立 |
> | 细节不精致 | 等宽字体被用于中文 | ✅ 成立 |

**"与 AdminLTE 2015 同构"** —— 这就是「没特色」的第一性定义。
不是不好看，是**任何人都认不出这是谁**。

### 2.3 更要紧的：文档承诺的东西，有一部分没发货

| 文档承诺 | 实际发货 | 判定 |
|---|---|---|
| 三套可选主题（墨玉/深空/极光） | `themes.css` 里**只有 `data-mode` / `data-density` / `data-radius`**，**没有 `data-accent` / `data-theme`** | ❌ **只发了一套蓝** |
| 品牌 4 色相 | 实测色相分布：210–239° 蓝 **33 个**、120–149° 绿 9 个、0–29° 橙红 8 个、30–59° 橙黄 8 个 | ✅ 都在，但绿/橙只作语义色出现在徽章里 |
| 布局脱开 AdminLTE | `--w-sidebar: 196px` / `--h-topbar: 96px`（从 236/52 改过） | ⚠️ 尺寸变了，**骨架仍是侧栏 + 顶栏 + 内容** |

**所以在"身份"这件事上，六轮下来净变化很小**：
品牌色是一个蓝、骨架是通用后台骨架、三套主题没发。

### 2.4 唯一有身份的那一版被跳过了

`ui-options/v4-agent.html`，标题 **「方案 4 · Agent 中心」**。我把它的内容抓出来看了，它长这样：

```
Agent 任务   3 个 · 1 完成 · 1 进行中 · 1 排队
⋯ 正在写入 cms-articles 的 2 行        来自 scaffold_resource · 12 秒前开始
◦ 排队中 product-reviews 声明校验       等待当前任务完成
✓ 已合并 shop-coupons 的声明            31 秒前 · 12 个字段 · 无冲突
文章列表   schema v1 · 自动生成
   01 laravel-12-queue  agent 写入中   审阅
```

**注意最后那几行**：状态是「agent 写入中」、操作按钮是「**审阅**」而不是「编辑」、
列头写着「**schema v1 · 自动生成**」。

**这是六轮里唯一一个能让人一眼说出"这是 AI 码农"的版本。** 它没被采纳。

## 三、真正的机会：框架的差异化，UI 里一个都没露

我把三个模板（`resource.blade.php` 1387 行 / `index.blade.php` 157 行 / `profile.blade.php` 302 行）
全部 grep 了一遍，找 AI / 自省 / 声明相关的东西：

```
packages/laravel/resources/views/index.blade.php:150:
  AI Agent 请阅读项目根目录的 llms.txt 与 AGENTS.md，或调用 php artisan mcp:start aimanong
```

**整份前后端模板里，跟"AI 码农"有关的就只有这一行提示文字。**

而框架实际握着一堆别人没有的能力 —— 后端接口**全都现成且实测可用**：

| 框架能力 | 后端现状 | UI 里可见吗 |
|---|---|---|
| 声明 → 四产物（JSON Schema / TS / OpenAPI / ai-context） | 编译期产出，`/__ai/openapi.json` 实测 200 | ❌ 完全不可见 |
| 自省能力清单 | `/__ai/capabilities.json` 实测 **200 / 219KB / 22 个顶层键** | ❌ |
| 声明校验（可带 requirements 对拍） | `POST /__ai/verify` 实测返回 `{"valid":true,"issues":[],"issue_count":0}` | ❌ |
| 跨框架对拍（同一份声明 Laravel / TP 行为一致） | 两端 e2e + 共享 fixture 已在跑 | ❌ |
| 可自愈异常（`did_you_mean` / `example` / `docs`） | core 里 5 个异常类都实现 | ❌ |

**这就是"独属于 AI 码农的前端效果"的真正素材**：
不是把表格做得更漂亮（那 6 轮已经试过了），
而是**把「声明式 / 可自省 / AI 协作」做成看得见、点得动的东西**。

顺手说一句：这五条里任何一条做出来，都**不可能被误认成别的后台** ——
dcat / 若依 / Filament / Nova 都没有「我把声明编译成了什么」、「这条报错建议我改成这样」。

## 四、两条路，成本差一个数量级

### 路线 A：重写前端（Vite + Vue 组件库）

**这条路上有一个已经写下的否决记录。**

`internal-docs/packages-ui-决策分析.md`（2026-10-11，结论：**不建议做**）：

> | 场景 | 需要 npm 包吗 | 原因 |
> |---|---|---|
> | ① 用 Aimanong 做后台的项目 | ❌ 不需要 | 他们只写 PHP Resource，前端由 Schema 自动渲染。给他 npm 包反而增加负担 |
>
> **「做个独立组件包」是个看起来专业、实际接不上线的动作。**
> 本项目的使用者零构建，npm 包到不了他们的运行时；

而且 `packages/ui/` **已经被删掉了**（按那份决策，我实测目录不存在）。

**所以路线 A 的实际含义是**：为了"更有特色"，把
「使用者零构建、装完即用」这条产品前提**换掉** —— 代价是每个用 Aimanong 的开发者
从此都要维护一套前端构建。**这笔账我认为不划算**，除非你的目标用户变了。

### 路线 B：在现有零构建架构里，加「一个专属面」

不引入构建、不进 npm、仍然是一个 blade 模板 + 内联 Vue。

**可行性我已经验过**：需要的接口全部现成 ——
`/__ai/capabilities.json`、`/__ai/openapi.json`、`/__ai/context`、`/__ai/menu`、
`POST /__ai/verify` 我逐个实测都是 200。

⚠️ 一个必须处理的前提：`/__ai/*` 走的是「仅 local/debug 或 `AIMANONG_AI_TOKEN`」那套守卫，
**与登录态无关**。所以页面里 `fetch` 直接打，在生产环境会被 401 挡掉 ——
这一条要么给页面加 token 透传，要么把这几个读接口按登录态放行（需要设计决定）。

## 五、我的建议

### 5.1 不要做的

- ❌ **不要**再做第 7 轮"配色/间距/暗色"迭代。6 轮的数据已经说明这条路的产出上限。
- ❌ **不要**引入 Vite + 组件库（理由见路线 A）。
- ❌ **不要**先改 UI，如果你还没想清楚"验收标准是什么"——
  上一轮 `ui-final` 出了 B 新芽 / C 纯白两个候选，最后发的是**深色**，说明当时的取舍标准并没有稳定下来。

### 5.2 建议做的（按顺序）

**第 0 步：先修我在截图里看到的三个基础问题**（比"特色"更影响观感）

| 现象 | 证据 |
|---|---|
| 列溢出，最右列被切 | 1440px 下列表页显示 `2026-10-11 04:39:0…`，右边被裁 |
| 图片列有破图占位 | 客户列表 2 行显示破损图标 |
| 首页 35 个快捷入口里，`订单` 出现 **3 次**、`客户` 2 次 | 实测 demo 里有 4 个 Order 类（Order/SaasOrder/ShipOrder/ShopOrder），**这是 demo 数据冗余，不是框架 bug** —— 但默认 demo 就长这样，第一印象会受影响 |

前两条是**真 bug**，第 3 条是 demo 该清理。

**第 1 步：做「声明实验室」这一个面**（投入产出比最高）

一个页面，三栏：

```
┌────────────┬──────────────────────┬─────────────────┐
│ 选择 Resource│ PHP 声明（只读/可粘贴）│ 四个产物，实时切换 │
│ cms-articles│ public static function│ ● JSON Schema   │
│ crm-customers│   grid(Grid $grid){   │ ○ TypeScript    │
│ shop-orders │     $grid->column(...  │ ○ OpenAPI       │
│ ...         │   }                    │ ○ AI 上下文      │
│            │                       │                 │
├────────────┴──────────────────────┴─────────────────┤
│ 校验结果：✅ 通过 / ❌ 3 个问题（每条带 did_you_mean）│
└─────────────────────────────────────────────────────┘
```

**为什么是这个**：
- 它直接演示了「声明唯一 + 四产物 + AI 可读」——**框架的全部卖点，一屏说完**
- 接口零新增（`/__ai/verify` + `/__ai/openapi.json` + `/__ai/context` 都已存在）
- 对"人（审阅者）"有真实用处：改完声明，不跑 CLI 就能看到四产物变成什么样
- 没有任何别的后台长这样

**第 2 步（可选）：能力地图**

把 `/__ai/capabilities.json` 的 22 个顶层键（field_types / rules / column_options /
tree_options / cannot_verify / unwired_props …）做成可搜索、可点开看例子的浏览器。

**这两步的共同点**：它们**不碰**现有 CRUD 页面 —— 那 6 轮做出来的设计系统继续用，
列表页/表单页保持不动。新增的是一个**新增的导航项**，风险可控。

### 5.3 需要你先定的三件事

1. **这个前端给谁看？**
   - 给**用 Aimanong 的开发者**看（那它得是后台的一部分，走路线 B）
   - 给**访客/潜在用户**看（那它是一个展示站，可以随便炫，不受零构建约束 —— 这是完全不同的项目）
   - 这两个答案会导出完全不同的方案，我上面默认按前者写

2. **验收标准是什么？**
   上一轮"更有特色"没有可判定的标准，导致做了 6 轮还在原地。
   建议这次先定死，例如：*"给一个没用过 Aimanong 的后端看一眼首页，能否说出它跟若依的区别"* ——
   这个能测，而且和 6 轮配色迭代的成败判若两回事。

3. **愿意投入多少？**
   声明实验室我估 **3–5 人日**（一个 blade + 内联 Vue + 三处接口接线 + 回归）。
   作为对比：`UI与基座方案.md` 里对当时那轮 UI 的估算是 **8–11 人日**，
   而那一轮的结果就是现在这套"扎实但无身份"的设计系统。

## 六、诚实的反面：什么情况下我的建议是错的

- **如果你要的其实只是"看起来更贵"**，那上面的路线 B 帮不上 ——
  那需要的是换骨架（例如从侧栏式改成命令面板式），成本比 3–5 人日高得多，而且**会破坏 Schema 渲染的稳定性**。
- **如果你的目标用户会自己写前端**，那路线 A 的否决理由就不成立了，
  独立组件包会变成一个真实需求 —— 但那时要重新评估的是**产品定位**，不是 UI。
- **如果声明实验室做出来，你自己不会天天用**，那它就是一个 demo，不该进产品包
  （会变成 AGENTS.md 里说的那种"声明了但没人消费"的东西）。
