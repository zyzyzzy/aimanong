# 多框架适配方案（Laravel / ThinkPHP）

> **目标**：让 Aimanong 的 DSL（`Resource` / `Grid` / `Form` / `Show` / `Tree`）同一套语法，
> 底层可跑在 Laravel 12 或 ThinkPHP 8 上，将来可扩展其它框架。

---

> ## ⚠️ 2026-10-13 修订：架构假设已被 PoC 推翻
>
> 实施 PoC 后（见 [多框架适配-PoC报告.md](./多框架适配-PoC报告.md)），本文档
> **「抽个接口 + 换实现」的路线不成立**：
>
> - `composer require aimanong/framework` 装进 ThinkPHP 8.1 项目后，
>   **ThinkPHP 启动即致命错误**（两个框架抢全局 `env()`），而 Composer 零冲突报告。
> - 所以障碍不在接口层，在 **Composer 依赖层** —— 必须**拆包**，
>   让 ThinkPHP 驱动永远不接触 `illuminate/*`。
>
> 本文档的分层耦合数据（第一节）经复核**全部准确**，仍然有效；
> 但第五节的实施路线请以 PoC 报告为准。

## 一、好消息：架构分层比预想的干净

实测耦合数据（`packages/framework/src`，124 文件 / 17598 行）：

| 层 | 文件 | 行数 | Illuminate 依赖 |
|---|---|---|---|
| **Grid / Form / Show / Tree**（DSL 层） | 40 | 2322 | **0 处** |
| **Schema 编译层**（核心枢纽） | 8 | 1304 | **3 处** |
| Auth / Http / Console / Mcp / Models | 约 40 | — | 约 80 处 |
| Foundation | 15 | — | 27 处 |

**DSL 层已经完全零 Laravel 依赖**——这意味着 `Resource::grid()`、`$grid->column()`、
`$form->text()` 这些语法**不需要任何改动**就能在 ThinkPHP 上跑。

需要适配的只有**驱动层**（约 80~100 处耦合，集中在 Controller / Auth / Repository / Console）。

---

## 二、需要适配的 6 个驱动域

| 域 | Laravel 现状 | ThinkPHP 对应 |
|---|---|---|
| **1. ServiceProvider** | `AimanongServiceProvider` 用 Laravel Container | `aimanong\Service`（ThinkPHP 8 的 service 机制） |
| **2. ORM / Model** | Eloquent `Model` + `casts()` | ThinkPHP ORM（支持 `$type` 属性映射） |
| **3. HTTP 路由/中间件** | `Route::middleware('admin')->group()` | ThinkPHP 路由 + 中间件（`app/middleware.php`） |
| **4. 认证** | `AdminGuard` + `AdminUserProvider` | ThinkPHP 的 `Auth` 鉴权驱动 |
| **5. Repository** | `EloquentRepository` 用 `Model::query()` | 新建 `ThinkRepository` 实现同一 `Repository` 接口 |
| **6. Console 命令** | `Command` + `Artisan::call()` | ThinkPHP 的 `console.php` + 命令类 |
| **7. 模板** | Blade `.blade.php` | ThinkPHP `think-template`（语法差异需适配） |

## 三、推荐方案：驱动层抽象 + 双实现

```
┌────────────────────────────────────────────────┐
│  DSL 层（零框架依赖，已就绪）                     │
│  Resource / Grid / Form / Show / Tree            │
├────────────────────────────────────────────────┤
│  Schema 编译层（仅 3 处耦合，易抽象）              │
├────────────────────────────────────────────────┤
│  驱动接口层（新增，本项目核心工作）                 │
│  RepositoryInterface / AuthDriverInterface /     │
│  RouteRegistrarInterface / ConsoleCommandInterface│
├────────────────────────────────────────────────┤
│  Laravel 驱动          │  ThinkPHP 驱动          │
│  EloquentRepository    │  ThinkRepository       │
│  LaravelGuard          │  ThinkGuard            │
│  BladeRenderer         │  ThinkTemplateRenderer │
└────────────────────────────────────────────────┘
```

### 关键设计原则

**1. DSL 层不感知框架**
`$grid->column('name', '姓名')->sortable()` 在两种框架下完全一致。
宪法第一条（AI 优先）要求这一点——AI 学一次语法，两个框架都能用。

**2. 驱动层用接口隔离**
新增 `packages/framework/src/Contracts/` 下的接口，由各框架的实现类注入。
ThinkPHP 支持自定义驱动，接入点清晰。

**3. Repository 是唯一需要双实现的核心**
`Repository` 接口已存在（`src/Contracts/Repository.php`），Eloquent 实现已就绪。
新增 ThinkPHP 实现即可，上层无感。

**4. 宪法合规检查**
- 第二条（声明唯一）：Schema 编译产物与框架无关，天然合规
- 第一条（AI 优先）：同一 DSL，AI 无需针对框架调整，反而**增强**合规性
- 第三条（零隐式）：`php artisan aimanong:install` vs `php think aimanong:install`
  需在能力面明确标注两条路径，不能只说一条

## 四、工作量估算

| 阶段 | 内容 | 预估 |
|---|---|---|
| **P0** | 抽出驱动接口（Repository / Auth / Route / Template） | 2~3 天 |
| **P0** | ThinkPHP Repository 实现（含 ScopeHooks / 关联加载） | 2~3 天 |
| **P1** | ThinkPHP Auth 驱动 + AdminGuard | 1~2 天 |
| **P1** | ThinkPHP 路由注册 + 中间件 | 1 天 |
| **P1** | 模板适配（Blade → think-template） | 3~5 天 |
| **P1** | Console 命令适配 | 1~2 天 |
| **P2** | e2e 双框架矩阵（同一 DSL 两个框架跑同一断言） | 2 天 |

**合计**：约 12~18 个工作日（单人）。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **模板适配工作量被低估** | Blade 的 `@{{ }}` 转义、`@include`、组件插槽与 think-template 差异大 | 先做 PoC：把 `resource.blade.php` 一个页面迁移过去，评估真实差异再排期 |
| **ThinkPHP ORM 的 casts/关联 API 与 Eloquent 有差异** | Repository 双实现需要处理不同行为 | 先写 `ThinkRepository` 的单元测试对照 Eloquent 行为，差异点显式记录 |
| **多框架导致测试矩阵翻倍** | 每次改动要跑两套 | e2e 层做框架无关断言（DSL 层），驱动层各自单测，避免全量翻倍 |
| **偏离「AI 优先」定位** | 如果为支持 TP 引入大量框架特定魔法，AI 会混乱 | 严格保持 DSL 层零框架依赖，所有框架特定逻辑进驱动层 |

## 六、我的判断：**值得做，但分两步**

### 第一步（PoC，2~3 天）
只做**模板 + Repository** 两个域的迁移，在 ThinkPHP 8 上让
一个最简单的 Resource（如「客户管理」）跑起来。

**目的**：验证工作量估算是否准确，尤其是模板适配的真实差异。
PoC 完成后再决定是否全面做。

### 第二步（全面适配，10~15 天）
PoC 通过后，按上表完成全部驱动适配 + 双框架 e2e。

---

## 七、需要你确认

1. **范围**：只做 PoC，还是直接全面适配？
2. **ThinkPHP 版本**：ThinkPHP 8.x 哪个小版本？
3. **优先级**：模板适配和 Repository，哪个先做？
4. **是否保留 Laravel 为主**：TP 作为可选驱动，还是双框架平等支持？
