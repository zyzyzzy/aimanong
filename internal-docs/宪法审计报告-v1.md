## 详细发现

### 3.5 第五条的反向测试（重点）

对两条断言做了破坏测试：

| 破坏操作 | 断言反应 | 判定 |
|---|---|---|
| `Tree::$draggable` 默认值改回 `true` | 断言仍通过，但**产物里 draggable 仍为 false** | ✅ 防御生效 |
| `Divider` 恢复 `$this->hidden(true)` | 断言正确失败（101/102） | ✅ 断言有效 |

第一个案例值得说明：断言通过**不是假绿灯**，而是**深层防御**：

```
第一层：断言检查源码字符串（protected bool $draggable = false）
第二层：draggable(true) 抛异常（即使默认值被破坏也无路径变成 true）
第三层：产物验证（真实产物里不得出现 draggable:true）
```

三层叠加，所以破坏任一层都不会导致谎报进入产物。

### 第三条的甄别过程

扫描出 24 个「三处都查不到」的方法，逐个甄别：

- **14 个是 getter / 内部方法**（`getBatchActions`、`toNodes`、`validationRules` 等）—— 非对外 API，忽略
- **10 个是 props 写入型**（`dateFormat`、`using`、`maxDepth` 等）—— 通过 `$this->props[...]` 间接工作，脚本按方法名搜所以漏掉
- **2 个重点确认**：
  - `omitWhenEmpty` —— 后端 `ResourceController:665` 有实现（提交时跳过空值），无 UI 效果但后端行为真实
  - `relation` —— 后端 `ResourceController:66-83` 有消费（关联列预加载）

均非幽灵能力。
