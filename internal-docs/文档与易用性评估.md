# 文档与易用性评估

> 2026-10-11 · 问题：「有没有一份完整的使用说明，让非程序员小白照着也能开发自己的 Web 系统？」

---

## 一、结论

**没有。而且差的不是「文档写得不够细」，是三个硬缺口。**

| 缺口 | 严重度 | 说明 |
|---|---|---|
| **① 装完无法登录（死锁）** | 🔴 **P0** | 安装命令不创建管理员账号，而后台必须登录才能进 |
| **② 全流程需要写 PHP 代码** | 🔴 **P0** | 建表要写 migration、建页面要写 Resource 类 |
| **③ 文档零面向非程序员** | 🟡 P1 | 现有文档 100% 假设读者会 PHP + Laravel + 命令行 |

**非程序员目前能走通的路：0 步。** 卡在第 1 步——连后台都进不去。

---

## 二、缺口①：装完进不去（P0，实测确认）

### 现状

`quickstart.md` 写着：

> 打开 `http://localhost:8000/admin`，**用安装时创建的账号**登录。

而实测 `aimanong:install` 的全部动作：

```
✓ 注册服务提供者到 bootstrap/providers.php
✓ 发布配置文件 config/aimanong.php
✓ 发布数据库迁移
✓ 数据库迁移完成
```

**没有任何一步创建账号。** 全仓库搜索 `Administrator::create` /
`firstOrCreate`（在 Console 与 database 目录下）→ **零命中**。

### 后果

```
装完框架 → admin_users 表为空 → 打开 /admin 跳登录页 → 没有账号可登
        → 进不去后台 → 也就无法用「管理员账号」界面创建第一个账号
```

**这是一个闭环死锁。** 使用者唯一的出路是手工执行 PHP：

```bash
php artisan tinker --execute='
$u = Aimanong\Models\Administrator::firstOrCreate(
    ["username" => "admin"],
    ["name" => "超级管理员", "password" => "admin123", "enabled" => true]
);
$r = Aimanong\Models\Role::firstOrCreate(
    ["slug" => "super_admin"], ["name" => "超级管理员", "is_super" => true]
);
$u->roles()->syncWithoutDetaching([$r->id]);
'
```

**这段代码不在任何一份对外文档里。** 它只存在于我自己的
`scripts/setup-demo.sh` 中 —— 也就是说：

> **我自己一直在用一段「使用者不可能知道」的脚本绕过这个断点，
> 所以这个断点从来没在我的验证里暴露过。**

### 为什么这是最严重的问题

前面几轮我反复强调「对『带地基的平台』来说，装完打不开是最不该有的问题」，
并为此修了 region 硬依赖（P0）。**但真正的「装完打不开」是这一条** ——
region 那条只是让页面 500，这条是**根本进不去**。

### 建议修复（约 1 小时）

1. `aimanong:install` 增加一步：创建管理员账号
   - 交互式询问用户名 + 密码（默认 `admin` / 随机强密码并打印）
   - 非交互模式（CI）用 `--admin-user=` / `--admin-password=` 或跳过
2. 同时创建 `super_admin` 角色并绑定，避免装完「登进去什么也看不到」
3. 修正 `quickstart.md` 的失实描述

## 三、缺口②：全流程要写代码（P0）

非程序员要做一套自己的系统，必须完成这些**不可跳过**的步骤：

| 步骤 | 现在怎么做 | 非程序员能完成吗 |
|---|---|---|
| 设计数据表 | 手写 Laravel migration（PHP 类） | ❌ |
| 执行迁移 | `php artisan migrate` | ❌ |
| 生成 Resource | `php artisan aimanong:make-resource {table}` | ❌ |
| 调整字段/标签 | 手改 Resource 类的 PHP 代码 | ❌ |
| 注册 Resource | 手改 Provider 的 PHP 代码 | ❌ |
| 配置权限 | `php artisan aimanong:permission sync` | ❌ |

**六个步骤全部需要敲命令行或写 PHP。**

### 但这里有个重要的判断

**这不是「框架没做好」，而是「产品形态没到那一步」。**

Aimanong 的定位是**给 AI Agent 用的框架** —— 它假设写代码的是 AI，
人是审阅者。在这个定位下，「需要写 PHP」不是缺陷，是设计。

真正的问题在**文档没有向非程序员交代清楚这一点**：

- 首页 tagline 说「让任何 AI Agent 在 5 分钟内理解框架」
- 但没有任何一处告诉非程序员：「你该怎么用这个项目」

非程序员其实有一条**现实可行的路**，只是没人写出来：

```
你不需要自己写代码，而是：
1. 装好框架（这一步找个会用命令行的人帮忙，或照图文步骤做一次）
2. 把需求用大白话告诉 AI（Claude / ChatGPT / Cursor）
3. AI 通过 MCP 直接操作你的项目，生成表与页面
4. 你在浏览器里验收、提修改意见
```

**这条路当前也走不通** —— 因为缺口①（进不去后台）会卡住第 4 步。

## 六、关于「非程序员使用说明」的方案

### 先说清楚一件事

要不要写这份文档，取决于一个**定位选择**：

**路线 A：保持「AI 写代码」定位**
→ 那么这份文档的名字不该是「开发手册」，而是
**「不懂编程，怎么用 AI 给自己造一个后台」**
→ 重点不是教编程，是教**怎么把需求讲给 AI**

**路线 B：转向低代码平台**
→ 需要做网页版建表/编辑器（P2 第 8、9 项，工作量大）
→ 文档就变成传统的「用户手册」

**我建议路线 A**，理由：

1. 符合项目初衷（给 AI 用的框架），不推翻现有架构
2. **成本极低** —— 框架已经支持了（MCP + 自省接口 + 可读错误），
   缺的只是一份**面向非程序员的引导文档**
3. 路线 B 意味着和若依/yudao 正面竞争，那是个红海，
   而且会背离「AI 优先」这个唯一的差异化

### 路线 A 的文档大纲（建议命名：`docs/guide/no-code.md`）

```
# 不懂编程，怎么用它给自己造一个后台

## 你需要准备什么
  - 一个能跑命令行的电脑环境（或找人装一次，10 分钟）
  - 一个 AI 助手（Claude / ChatGPT / Cursor 任一）
  - 你的业务想法

## 第一步：把框架装起来（照抄即可，附截图）
  <逐条命令 + 每步预期输出>

## 第二步：认识三个词就够
  - 数据表 = 你要管理的东西（客户、订单、设备…）
  - 字段 = 这个东西有哪些信息（姓名、金额、日期…）
  - 后台页面 = 自动生成的增删改查界面
  <用「客户表」举例，全程大白话>

## 第三步：把需求讲给 AI（关键章节）
  - 怎么描述需求（附可直接复制的模板）
  - 好的描述 vs 坏的描述对比
  - 示例对话全过程

## 第四步：在浏览器里验收
  - 打开哪、看什么、怎么提修改意见

## 常见问题
  - 登不上后台怎么办
  - AI 生成的字段不对怎么办
  - 改错了怎么回退
```

### 工作量

| 部分 | 依赖 |
|---|---|
| 第一、三、四、五章 | 现在就能写 |
| **第二章（装起来）** | **必须先修缺口①**，否则第一步就断了 |

## 七、我的建议顺序

| 顺序 | 事项 | 工作量 | 为什么这个顺序 |
|---|---|---|---|
| 1 | **修安装命令的账号创建**（P0） | ~1 小时 | 不修的话，任何文档第一步就断 |
| 2 | 修正 `quickstart.md` 失实 | ~10 分钟 | 同一件事 |
| 3 | **写「非程序员使用指南」** | ~半天 | 你问的正是这个 |
| 4 | 术语表 + FAQ | ~2 小时 | 配合 3 一起 |
| 5 | 网页版建表/编辑器 | 数天 | 需要单独决策定位 |

**先做 1 和 2**（都是小改动、且是硬阻塞），再做 3。
