# Aimanong —— AI-First 后台开发框架

> **一个专为 AI Agent 设计的 Laravel 12 后台开发框架**
> 让任何 AI Agent 在 5 分钟内理解框架、30 分钟内产出可用的后台系统。

| 项 | 值 |
|---|---|
| 项目名 | **Aimanong**（AI 码农） |
| 域名 | aimanong.com / .net / .cn |
| 定位 | **AI-First**：使用方是 AI Agent，人是审阅者 |
| 基座 | Laravel 12+（PHP ^8.2） |
| 前端 | Vue 3 + TypeScript + Element Plus |
| 许可 | 开源（MIT），GitHub + Gitee 双仓 |

---

## 一、核心命题：什么是"给 AI 用的框架"

这是本方案与上一版最根本的区别。**AI-First 不是"文档写好一点"，而是架构层面的重新设计。**

人要的是：优雅的抽象、灵活的扩展、渐进式的学习曲线。
AI 要的是：**低歧义、可自省、可验证、错误可自愈、无需记忆大量上下文。**

两者经常冲突。举例：dcat 的 `Grid::column()` 支持十几种重载签名，人看了觉得灵活，AI 看了会产生歧义。**在 AI-First 框架里，我们明确牺牲"灵活性"换取"确定性"。**

### 1.1 AI Agent 使用框架的四大痛点（我们要解决的）

| 痛点 | 现象 | Aimanong 的解法 |
|---|---|---|
| **不知道有什么** | Agent  hallucinate 出不存在的类/方法 | **自省 API**：`ai:capabilities` 列出全部能力，机器可读 |
| **不知道怎么用** | 参数组合猜错，反复试错 | **单一规范签名** + Schema 即文档 |
| **不知道错在哪** | 报错信息不 actionable，死循环 | **可自愈错误**：报错直接给出修正建议与正确示例 |
| **改了不知道对不对** | 无法验证，只能靠人肉检查 | **验证器 + 自检**：`ai:verify` 生成后自动校验 |

### 1.2 设计哲学（写进项目 README 第一条）

1. **Schema 是唯一真相**：一份 PHP 声明同时产出运行时 UI、JSON Schema、TypeScript 类型、OpenAPI 文档、AI 提示词。**杜绝文档与实现漂移**——这是 AI 出错的最大来源。
2. **零隐式魔法**：不用 `__call`、不用 trait 堆叠、不用运行时字符串拼类名。AI 静态读代码即可推断全部行为。
3. **错误即教学**：每条异常必须携带 `didYouMean` + 正确用法示例。
4. **可自省**：框架能回答"你有哪些能力"，而不只是"你有哪些类"。

## 三、让 AI 快速上手的五层设计（核心卖点）

这是整个方案的重点。**AI 不是靠读文档学会框架的，是靠"发现—调用—试错—验证"闭环。** 我们把这个闭环做成框架内建能力。

### 第 1 层：`llms.txt` —— AI 的第一入口

在仓库根与文档站根放置 [`llms.txt`](https://github.com/AnswerDotAI/llms-txt)（已成为事实标准，Claude/Cursor 等会主动抓取）：

```
# Aimanong

> AI-First admin framework for Laravel 12. Define Grid/Form in PHP, render in Vue 3.

## 核心概念（AI 必读，约 1200 token）
- Resource：一张表对应一个 Resource 类
- Grid：列表页声明式定义
- Form：表单页声明式定义
- 所有声明最终编译为 JSON Schema

## 快速上手
- [5分钟上手](./llms/quickstart.md)
- [Grid 完整字段参考](./llms/grid.md)
- [Form 完整字段参考](./llms/form.md)
- [错误码与修正](./llms/errors.md)

## 机器可读
- 能力清单: GET /__ai/capabilities.json
- OpenAPI: GET /__ai/openapi.json
```

配套 `llms-full.txt`（完整版，给需要深度上下文的场景）。

### 第 2 层：`AGENTS.md` —— 项目内约定

仓库根目录放 `AGENTS.md`（Agent 编码规范，已被主流工具支持），规定：
- 生成代码必须放哪个目录、命名规范
- 生成后必须跑 `php artisan ai:verify`
- 禁止使用的写法（如裸调 Carbon `diffIn*`）

**这一条极其关键**：它让 Agent 在别人的 Aimanong 项目里也能立刻知道规矩，无需重新学习。

### 第 3 层：自省 API —— 让框架自己告诉 AI 它有什么

内建路由（默认仅 local/debug 开启，生产需 token）：

```
GET  /__ai/capabilities.json    # 全部能力清单：Resource/字段类型/展示器/动作
GET  /__ai/openapi.json         # 全量 OpenAPI 3.1
GET  /__ai/schema/{resource}    # 某个 Resource 的完整 Schema
GET  /__ai/examples/{pattern}   # 可复制的代码片段（grid/form/tree/...）
POST /__ai/verify               # 校验一段声明是否合法
```

`capabilities.json` 示例（**这就是 AI 的"记忆体"**）：

```json
{
  "version": "1.0.0",
  "resources": [{
    "name": "User",
    "uri": "users",
    "fields": [
      {"name":"id","type":"integer","readonly":true},
      {"name":"name","type":"string","required":true,"max":255},
      {"name":"email","type":"string","rules":["email"]}
    ],
    "grid": {"searchable":["name","email"],"filters":["status"]},
    "form": {"fields":["name","email","status"]}
  }],
  "field_types": {
    "text": {"php":"Aimanong\\Form\\Fields\\Text","props":{"placeholder":"string"}},
    "select": {"php":"Aimanong\\Form\\Fields\\Select","props":{"options":"array|callable"}}
  }
}
```

### 第 4 层：MCP Server —— 让任何 AI 客户端直接操作（**最大差异化**）

用官方 **[laravel/mcp](https://github.com/laravel/mcp)**（已实测：v0.4.2，支持 Laravel 12，支持 2025-11-25 协议，提供 `make:tool`/`make:server` 脚手架，stdio + HTTP 双传输）。

内建 MCP Tools：

| Tool | 作用 |
|---|---|
| `list_resources` | 列出所有 Resource 及其字段 |
| `describe_resource` | 获取某 Resource 的完整定义与用法 |
| `scaffold_resource` | **从数据库表一键生成 Resource** |
| `create_page` | 生成 Grid/Form/Show 页面代码 |
| `validate_declaration` | 校验声明合法性，返回修正建议 |
| `run_verify` | 执行项目自检（路由/权限/迁移一致性） |
| `query_data` | 只读查询数据，便于调试 |
| `search_docs` | 语义检索文档 |

MCP Prompts：
- `new-admin-module` —— "帮我生成一个 XX 管理模块"的标准流程
- `debug-error` —— 传入异常，获取修正方案

> **这是相对 Filament/owl-admin 的绝对差异化：它们面向人，Aimanong 通过 MCP 直接长在 AI 的工作流里。** AI 不需要"读文档"，它直接调工具。

### 第 5 层：可自愈错误 —— 让 AI 一次改对

错误信息必须结构化、可机器消费：

```json
{
  "error": "UNKNOWN_FIELD_TYPE",
  "message": "字段类型 'texte' 不存在",
  "did_you_mean": "text",
  "location": "app/Aimanong/UserResource.php:42",
  "hint": "可用类型: text, textarea, select, switch, date, ...",
  "example": "$form->text('name')->required();",
  "docs": "https://aimanong.com/llms/fields.md#text"
}
```

配套约定：
- 所有异常实现 `AiReadableException` 接口，强制提供 `didYouMean()` / `example()
`
- 方法名/字段名做**编辑距离模糊匹配**，AI 打错也能得到正确提示

## 四、架构设计

### 4.1 分层

```
┌──────────────────────────────────────────────────────┐
│ 消费层（三种客户端，同一套 Schema）                      │
│  ├─ 人：Vue 3 SPA（Element Plus）                      │
│  ├─ AI：MCP Server / 自省 API                          │
│  └─ 第三方：REST API（OpenAPI 3.1）                    │
├──────────────────────────────────────────────────────┤
│ Schema 编译层（核心）                                   │
│  PHP 声明 → Schema AST → {JSON Schema, TS 类型,        │
│                           OpenAPI, AI 提示词, 运行时UI} │
├──────────────────────────────────────────────────────┤
│ DSL 层                                                 │
│  Resource / Grid / Form / Show / Tree / Action          │
├──────────────────────────────────────────────────────┤
│ 基础设施                                               │
│  认证(admin guard) / RBAC / 菜单 / 插件 / 代码生成器     │
└──────────────────────────────────────────────────────┘
```

**关键点：Schema 编译层是整个框架的枢纽。** 一份声明编译出所有产物，从根上消灭文档漂移。

### 4.2 代码形态（AI 友好：声明式、无魔法）

```php
<?php

namespace App\Aimanong;

use Aimanong\Resource;
use Aimanong\Form\Fields\{Text, Select, SwitchField};

class UserResource extends Resource
{
    public string $model = \App\Models\User::class;
    public string $label = '用户';
    public string $uri  = 'users';

    public function grid(Grid $grid): void
    {
        $grid->column('id', 'ID')->sortable();
        $grid->column('name', '姓名')->searchable();
        $grid->column('email', '邮箱')->searchable();
        $grid->column('status', '状态')->using(Status::class)->filter();
        $grid->column('created_at', '创建时间')->dateTime();
    }

    public function form(Form $form): void
    {
        $form->text('name')->label('姓名')->required()->max(255);
        $form->text('email')->label('邮箱')->required()->rules('email');
        $form->select('status')->label('状态')->options(Status::cases());
    }
}
```

设计约束（**AI-First 专用，与常规框架不同**）：
- **方法签名唯一**：`text(string $name)` —— 不做多重载，杜绝歧义
- **链式调用扁平**：不嵌套闭包（AI 生成嵌套闭包极易出错）
- **类型即校验**：`->required()` / `->max(255)` 直接编译为 Laravel 验证规则 + 前端校验
- **枚举优先**：状态类字段鼓励用 PHP Enum，编译为 JSON Schema `enum`

### 4.3 从 dcat 继承什么

| dcat 资产 | 处置 | 说明 |
|---|---|---|
| Grid/Form/Show/Tree 四件套思想 | ✅ 继承 | 最核心资产 |
| Repository 数据源抽象 | ✅ 继承 | 松耦合优秀 |
| Section 注入 | ✅ 简化继承 | 插件扩展点 |
| 多应用 | ✅ 继承 | 借 Laravel 12 Context 简化 |
| jQuery/pjax/AdminLTE | ❌ 抛弃 | 技术债根源 |
| 67 字段 / 28 展示器 / 25 Widget | ⚠️ **分期重写为 Vue 3** | 按使用频次排优先级 |

### 4.4 Laravel 12 兼容性：已完成实证

上一版方案已在本机真实安装 **Laravel 12.69.3**（PHP 8.2.29 / Symfony 7.4.20 / Carbon 3.14.2）跑通探针，结论沿用：

- ✅ dcat 的核心启动流程在 L12 上 **8/11 通过**（中间件别名、配置注入、路由动态注册、Blade 等均正常）
- ❌ 需处理的硬断点：认证契约新增 `rehashPasswordIfRequired()` / `getAuthPasswordName()`、`AuthenticationException::redirectTo($request)` 必须传参、Carbon 3 的 `diffIn*` 返回负数 float、doctrine/dbal 不再自带、`Blueprint` 需传 Connection、骨架无 Kernel 需改写入 `bootstrap/providers.php`、`filesystems.local.root` 默认变 `storage/app/private`
- ✅ 已证伪两条谣言：`Str` 有 115 个静态方法零移除；`EventServiceProvider`/`RouteServiceProvider` 类仍在

**新增验证**：`laravel/mcp v0.4.2` 在 Laravel 12 上依赖解析通过，支持 2025-11-25 协议，官方提供 `make:tool` 等脚手架 —— MCP 路线技术可行。

> 内部约定：时间计算统一走框架封装（如 `Duration::daysBetween()`），**禁止裸调 `diffIn*`**，从根本上规避 Carbon 3 负数静默错误。

## 五、给人看的文档（你要求的第 5 点）

虽然是 AI-First，但人是审阅者和决策者，文档必须完备。

| 文档 | 读者 | 形态 |
|---|---|---|
| `llms.txt` / `llms-full.txt` | AI | 纯文本，控制在 token 预算内 |
| `AGENTS.md` | AI Agent | 项目内约定 |
| **使用文档站** | **人** | VitePress，中英双语 |
| `capabilities.json` / OpenAPI | 机器 | JSON |
| 交互式 Playground | 人 | 在线改 PHP 声明，实时看 UI |

文档站结构（给人）：快速上手 → 核心概念 → Resource/Grid/Form/Show 参考 → 字段类型手册 → 扩展开发 → **AI 协作指南（教人怎么指挥 AI 用本框架）** → 从 dcat/Filament 迁移。

> 特别说明：文档站**由同一套 Schema 自动生成 API 参考部分**，手写只写教程类内容。这保证了文档永不漂移。

## 六、开源与工程化

### 6.1 仓库规划

| 仓库 | 内容 |
|---|---|
| `aimanong/framework` | 核心（Composer 包） |
| `aimanong/ui` | Vue 3 组件库（npm） |
| `aimanong/docs` | 文档站 |
| `aimanong/demo` | 示例项目 |

双平台：GitHub（主）+ Gitee（国内镜像，自动同步）。

### 6.2 必备工程化

- **CI**：GitHub Actions + Gitee 镜像同步；PHPUnit/Pest 单测 + Vitest 前端测试
- **质量门禁**：PHPStan Level 8 + Pint + ESLint/TS 严格模式
- **AI 回归测试（本项目特色）**：维护一个"AI 任务集"（如"生成一个带搜索和导出的用户管理"），每次发版用多个 LLM 跑一遍，**统计一次成功率**。这是 Aimanong 的核心质量指标。
- **安全**：从第一天起统一转义层 + 公开安全响应流程（相对 dcat 最直观的卖点，dcat 有 4 条 CVE 零补丁）
- **版本**：SemVer；约束 `laravel/framework: ^12.0|^13.0`

## 七、排期与里程碑

| 阶段 | 内容 | 工期 |
|---|---|---|
| **M0 地基** | Laravel 12 骨架、admin guard（新契约）、RBAC、菜单、API 层、统一响应/错误 | 3~4 周 |
| **M1 Schema 编译层** | PHP 声明 → AST → JSON Schema / TS / OpenAPI | 3~4 周 |
| **M2 核心 DSL + Vue** | Grid / Form / Show + 对应 Vue 组件，端到端跑通 | 6~8 周 |
| **M3 AI 能力层** ⭐ | llms.txt、AGENTS.md、自省 API、**MCP Server**、可自愈错误 | **3~4 周** |
| **M4 字段/组件库** | 分期重写字段与展示器（先 Top 20） | 8~10 周 |
| **M5 增强** | Tree、分步表单、导入导出、多应用、插件系统 | 4~6 周 |
| **M6 生态与文档** | 代码生成器、文档站、示例项目、AI 任务集回归 | 4~6 周 |

**合计约 31~42 周（7~10 个月）**，2 人小组可压缩至 5~7 个月。

> **建议调整优先级：把 M3（AI 能力层）提前到 M2 之后立刻做。** 因为 AI-First 是本项目的卖点，应尽早验证"AI 真的能顺畅使用"这一核心假设，而不是等组件库做完。

**本周可启动的垂直切片**：只做 `Grid` 一条链路（PHP 声明 → Schema → Vue 表格 → 分页/搜索/排序）+ 一个最小 MCP tool，**两周内端到端跑通**，用真实效果验证架构。

## 八、风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| **AI 一次成功率不达标**（核心假设失效） | **高** | M3 阶段就用多模型实测；建立 AI 任务集回归，把成功率作为发版门禁 |
| MCP 生态变化快（协议/客户端） | 中 | 用官方 laravel/mcp 跟随升级；自省 API 独立于 MCP，不把鸡蛋放一个篮子 |
| 组件数量大导致工期膨胀 | 高 | 分期交付，先 Top 20 字段；预留 `CustomComponent` 逃生舱 |
| 与 Filament/owl-admin 竞争 | 中 | **不打同一维度**：它们服务人，我们服务 AI；MCP 是护城河 |
| 前端复杂度（Vue3 + Laravel 混合部署） | 中 | Docker + 官方部署文档；构建产物随包发布 |
| Laravel 13 破坏性变更 | 低 | 抽象版本适配层，约束写 `^12\|^13` |
| 开源无人参与 | 中 | 文档站 + AI 协作指南降低门槛；明确 Good First Issue |

## 九、建议的第一步

1. **确认名字与域名**：注册 `aimanong/framework` 包名，定 Logo。
2. **建立"AI 一次成功率"这个北极星指标** —— 这是 Aimanong 区别于所有竞品的量化标准，建议从第一天就开始测。
3. **两周垂直切片**：Grid 单链路 + 最小 MCP tool，端到端验证。
4. **同步启动 `llms.txt` 初稿**：哪怕框架还没写完，先把 AI 契约定下来，反过来指导 API 设计（**AI-First 的正确做法：先定契约，再写实现**）。
