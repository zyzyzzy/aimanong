## 任务：给「设备报修」做一套管理后台

我们公司内部有个设备报修流程，现在想搬进后台。数据库表已经建好了
（`equipment_repairs`），你不用管建表，只要做出管理界面。

### 业务需求（请逐条满足）

1. **报修单列表**
   - 能看到：报修单号、设备名称、报修人、状态、紧急程度、报修时间、处理人
   - 要能按**设备名称**和**报修人**搜索
   - 要能按**报修时间**排序
   - 列表要能**导出**给行政部做月度统计

2. **状态与紧急程度要显示得直观**
   - 状态有三种：待处理(`pending`)、处理中(`processing`)、已完成(`done`)
   - 紧急程度有三种：一般(`normal`)、紧急(`urgent`)、非常紧急(`critical`)
   - 这两个字段在列表里要显示**中文**，而且要**不同值不同颜色**，
     让人一眼看出哪些是紧急的
   - 运营希望以后能自己改这些文案和颜色，**不希望每次改文案都找开发**

3. **报修单填写**
   - 报修单号必填且唯一
   - 设备名称、报修人必填
   - 故障描述用多行文本
   - 现场照片：**要能传多张**
   - 相关附件（如维修报价单）：**要能传多个文件**
   - 报修时间
   - 处理人和处理时间（处理完了才填）

4. **处理留痕**
   - 谁在什么时候把哪条报修单的状态改成了什么，**事后要能查得到**
   - 这个我希望能自动记，不想让开发在每个地方手写

5. **权限**
   - 这是一套内部系统，**不同岗位看到的东西应该不一样**
   - 但现在先跑起来，权限可以后面配

### 交付要求

- 写好的 Resource 放到 `app/Aimanong/`，注册到 `app/Providers/AimanongResourceProvider.php`
- 完成后必须自己跑一遍框架提供的校验命令，确保通过

## 验收方式（父 Agent 执行，不告知子 Agent）

逐条核对，并**独立复核**（不轻信自述）：

| # | 验收项 | 对应考察的能力 |
|---|---|---|
| 1 | 列表列完整 | 基础 |
| 2 | `equipment_name` + `reporter` 可搜索 | `searchable()` |
| 3 | `reported_at` 可排序 | `sortable()` |
| 4 | 开启导出 | `export()` |
| 5 | 状态/紧急程度显示中文 | 发现字典 **或** `map()`/`options()` |
| 6 | 状态/紧急程度**不同值不同颜色** | **字典 color**（v1.6.0） |
| 7 | 「运营可自己改文案」被满足 | **数据字典**（v1.6.0）而非硬编码 |
| 8 | `repair_no` 必填 | `required()` |
| 9 | 多图上传 | **`images()`**（v1.6.0） |
| 10 | 多文件上传 | **`files()`**（v1.6.0） |
| 11 | 处理留痕可查 | 发现**内置操作日志**（v1.6.0）而非自己建表 |
| 12 | 框架校验通过 | `ai:verify` |
| 13 | 未读源码 | 硬性约束 |

### 评分标准（沿用前五轮）

| 结果 | 得分 |
|---|---|
| 一次生成即可运行，校验全绿，13 项全满足 | **1.0** |
| 需 1 次修正（读错误信息后自行改对） | **0.5** |
| 需 ≥2 次修正，或需人工介入 | **0** |

**额外关键指标：发现率** —— 第 6/7/9/10/11 项属于 v1.6.0 新能力，
