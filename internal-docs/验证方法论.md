# 验证方法论（血泪版）

> 这份文档记录**验证工具本身出错**的记录。
>
> 背景：Aimanong 是「给 AI 用的框架」，AI 的产出必须可被验证。
> 但在开发过程中，**验证脚本自己已经给出了至少 6 次错误结论**——
> 其中 4 次让我去修一个并不存在的 bug，浪费了大量时间。
>
> 结论先行：**「验证器没报错」不等于「东西是对的」；
> 「验证器报错了」也不等于「东西是错的」。** 两边都要怀疑。

---

## 一、截图类验证的坑

### 1.1 入场动画没推进 → 弹窗被拍成半透明（最耗时的一次）

**现象**：真机截图里，表单弹窗是半透明的，背后的表格清清楚楚地"透"出来，
看起来像 `z-index` 或 `position` 层级错了。

**实际排查过程**（走了很多弯路）：

| 假设 | 验证 | 结论 |
|---|---|---|
| z-index 太低 | `elementsFromPoint` 返回 `am-modal > am-overlay > table` | 层级是对的，❌ 假设不成立 |
| `backdrop-filter` 的锅 | 移除后问题依旧 | ❌ |
| `user-prefs.css` 叠加了遮罩 | 逐个禁用样式表 | ❌ 只是让外层变亮了一点 |
| 父元素 background 盖住了子元素 | 把 overlay 涂成纯红、modal 涂成纯蓝 | 弹窗区域是 **红色**（overlay 盖住了 modal）→ 看起来假设成立 |

到这里几乎要动手改层级了。**最后一步才对**：

```js
// 关掉所有动画后再截图
*, *::before, *::after { animation: none !important; transition: none !important }
```

→ 弹窗立刻变成纯白不透明，一切正常。

**真因**：`.am-modal` 有 `animation: am-modal-in`（`opacity: 0 → 1`）。
在本机（**无显示器 / 软件合成**，`screencapture` 直接报
`could not create image from display`）动画时钟**不推进**，
弹窗被永久定格在约 27% 的透明度上。
再叠加 overlay 自己的 `am-fade-in`，就出现了"表格透过弹窗"的错觉。

**给验证脚本的硬性要求**：

> 截图前必须先注入 `animation:none; transition:none`，
> 否则任何带入场动画的组件都会被拍成中间态。

### 1.2 `sips -c` 从**中心**裁剪，不是左上角

用 `sips -c H W` 想裁左上角的一块，实际裁的是中心。
连续 4 次裁到错误区域，导致我一路去追一个「LOGO 没渲染」的幽灵 bug。

**改用** Python `PIL.Image.crop((left, top, right, bottom))`，
参数语义明确，不会搞错。

### 1.3 CDP `clip` 参数必须是数字

```
Protocol error (Page.captureScreenshot): Invalid parameters
Failed to deserialize params.clip.width - BINDINGS: double value expected
```

`clip.width/height/x/y` 传了非数字或 `NaN` 就会这样。
**再说一次**：截图存下来后，一定要确认它**真的拍到了你想看的区域**
（读一次像素、或看尺寸），不要拿到文件就当成功。

## 二、CSS 类验证的坑

### 2.1 "CSS 已加载" ≠ "样式生效"

`<link>` 是 200、文件内容也对，但页面上完全没有样式。
真因是资源路由用 `response()->file()` 返回 `.css`，
MIME 被猜成 `text/html`，浏览器**拒绝解析**（`cssRules.length === 0`）。

**验证方式**：不要只看网络请求成功，要检查
`document.styleSheets[i].cssRules.length > 0`。

### 2.2 加载顺序陷阱（踩了三次）

| 现象 | 真因 |
|---|---|
| 切主题没反应 | `design-system.css` 的兜底 `:root` 排在 `themes.css` **之后** |
| 登录页品牌名不消失 | media query 里的 `.lg__brand{display:none}` 写在基础规则**之前** |
| 汉堡按钮在小屏不出现 | `.am-menu-toggle{display:none}` 覆盖了 media query |

**规则**：`design-system.css → themes.css → user-prefs.css` 顺序不可变；
media query 必须写在它要覆盖的基础规则**之后**。

### 2.3 "CSS 里有这条规则" ≠ "元素用得上这个类"

多次出现「CSS 写好了，模板却没加类名」的幽灵能力：

| CSS 里的选择器 | 模板实际输出 | 后果 |
|---|---|---|
| `.am-step__label` | `<span>`（无类名） | 步骤条把整段 JSON 打印出来 |
| `.am-switch__track` | `<span>`（无类名） | 开关 0×0，完全不可见 |
| `.am-table-wrap--stack` | 模板有、CSS 当时没有 | 卡片模式是死代码 |
| `.am-shell.is-nav-open` | 没有按钮、没有 JS | 整条响应式路径是死代码 |

**结论**：**样式和模板必须成对验证**。
加了一个 CSS 类，就要 grep 一次模板里到底有没有它；
加了一个模板类，就要确认 CSS 里真的有规则。

## 三、"静默错误"清单（模板渲染类）

这类错误**不会报错、不会让测试变红、PHPStan 也看不出来**，
只会在浏览器里静静地显示错东西。已发生 3 次：

| 缺陷 | 表面现象 | 真实原因 |
|---|---|---|
| 步骤条显示 JSON | 顶部四大段 JSON | `@{{ s }}` 其中 `s` 是对象，应为 `s.title` |
| 选项显示 JSON、值全是 0/1/2 | 下拉框文案是 `{ "value": 1, ... }` | 数组被当对象遍历，Vue 解构拿到的是下标 |
| 必填下拉框显示空白 | 框是空的，用户以为坏了 | `v-model` 绑上 `undefined` → `selectedIndex = -1` |

**防御手段**：把「数据形状」和「模板写法」都写成测试
（见 `tests/Unit/FormOptionContractTest.php`）。

## 四、必须用真交互验证，不能只读 DOM/CSS

例：侧栏缩窄后开关按钮点不到。
只量 `getBoundingClientRect()` 只会看到"按钮位置看着还行"，
真因是**悬浮展开让侧栏从 64px 变 196px，按钮跟着位移了 128px**——
只有真的按下鼠标、并对比按下前后的坐标，才能发现（实测位移 1px 为正常）。

**推荐做法**：

```js
document.elementFromPoint(x, y)   // 命中测试：用户点这里会点到谁
await mouse.click(x, y)           // 真鼠标事件，不是 el.click()
```

## 五、一句话总结

1. **验证器是人写的，也会错** —— 本仓库已知 6 次假结果。
2. **沉默比报错更危险** —— "没输出" 往往意味着检查根本没跑起来。
3. **看到异常先问"是不是我的观测手段坏了"** —— 特别是截图和自动化脚本。
4. **同一个结论要有两个独立来源** —— 例如 DOM 命中测试 + 像素采样。
5. **能测的形状就写成测试** —— 别指望下次还记得这个坑。
